# RepoReaper GitHub 仓库处理说明

## 📋 核心问题回答

### ❓ 这个项目处理了 GitHub 仓库的什么内容？

**答案：项目处理的是代码仓库中的文本文件，主要是源代码文件，采用智能选择性下载策略，而非全量下载。**

---

## 🔍 详细说明

### 一、文件过滤策略

项目在获取仓库结构时，会**自动过滤**以下内容：

#### 1.1 被忽略的文件扩展名

```python
IGNORED_EXTS = {
    '.png', '.jpg', '.jpeg', '.gif', '.svg', '.ico', '.mp4',  # 图片和视频
    '.pyc', '.lock', '.zip', '.tar', '.gz', '.pdf',            # 二进制和压缩文件
    '.DS_Store', '.gitignore', '.gitattributes'                 # 系统文件
}
```

**原因**：
- 图片、视频等二进制文件无法进行代码分析
- 编译产物（.pyc）和压缩包不包含源代码
- 系统配置文件对代码理解帮助有限

#### 1.2 被忽略的目录

```python
IGNORED_DIRS = {
    '.git', '.github', '.vscode', '.idea',      # 版本控制和 IDE 配置
    '__pycache__', 'node_modules', 'venv',      # 依赖和虚拟环境
    'env', 'build', 'dist', 'site-packages',     # 构建产物和安装包
    'migrations'                                 # 数据库迁移文件（通常自动生成）
}
```

**原因**：
- 依赖目录（node_modules, venv）通常体积巨大且对理解核心逻辑帮助不大
- 构建产物（build, dist）是编译后的文件，不是源代码
- IDE 配置和版本控制文件不包含业务逻辑

#### 1.3 保留的文件类型

项目会处理以下类型的文件：

**代码文件**：
- Python: `.py`
- Java: `.java`
- JavaScript/TypeScript: `.js`, `.ts`, `.jsx`, `.tsx`
- Go: `.go`
- C/C++: `.cpp`, `.c`, `.h`
- C#: `.cs`
- Rust: `.rs`
- PHP: `.php`

**配置文件**：
- Markdown: `.md` (包括 README.md)
- 配置文件: `.json`, `.yaml`, `.yml`, `.toml`, `.ini`, `.conf` 等

**其他文本文件**：
- 文档文件、脚本文件等可读文本文件

## 📥 下载策略：智能选择，非全量下载

### 二、三阶段下载策略

项目采用**渐进式智能下载**，而非一次性下载所有文件：

#### 阶段 1: 获取文件列表（仅路径，不下载内容）

```
GitHub API → 获取所有文件路径 → 过滤 → 生成 file_list[]
```

**操作**：
- ✅ 获取所有符合条件的文件路径
- ❌ **不下载文件内容**
- 目的：建立仓库的"目录索引"

**示例**：
假设仓库有 1000 个文件，此阶段只获取 1000 个文件路径，不下载任何内容。

#### 阶段 2: 生成仓库地图（Repo Map）- 选择性下载

**策略**：只下载**优先级最高的 15-20 个文件**来提取符号签名

```python
# 优先级筛选规则
priority_exts = ('.py', '.java', '.go', '.js', '.ts', '.tsx', '.cpp', '.cs')
priority_keywords = ['main', 'app', 'core', 'api', 'service', 'utils', 'controller', 'model']

# 选择条件：
# 1. 文件扩展名匹配
# 2. 路径层级 <= 2 层 或 包含关键词
# 3. 最多选择 15 个文件
```

**下载内容**：
- 只下载文件内容用于提取符号（类名、函数名）
- 提取后只保留符号信息，不保留完整代码
- 其他文件只保留路径信息

**示例**：
- 仓库有 1000 个文件
- 此阶段只下载 15 个关键文件（如 `main.py`, `app/core.py`, `api/service.py`）
- 提取这些文件的类和函数签名
- 生成包含所有 1000 个文件路径 + 15 个关键文件符号的 Repo Map

#### 阶段 3: LLM 智能选择（深度分析）- 再下载 3-9 个文件

**策略**：LLM 根据 Repo Map 智能选择 1-3 个最关键的文件进行深度分析

```python
MAX_ROUNDS = 3  # 最多 3 轮选择
每轮选择 1-3 个文件
```

**流程**：
1. LLM 分析 Repo Map（包含所有文件路径 + 关键文件符号）
2. LLM 选择 1-3 个最关键的文件
3. 下载这些文件的完整内容
4. 进行 AST 解析和代码分块
5. 存储到向量数据库
6. 重复 3 轮（如果 LLM 认为还需要更多信息）

**下载内容**：
- 下载文件的完整源代码
- 进行智能分块（AST 感知）
- 生成向量嵌入
- 存储到向量数据库

**示例**：
- 第 1 轮：LLM 选择 `app/main.py`, `app/services/auth.py` → 下载 2 个文件
- 第 2 轮：LLM 选择 `app/core/config.py` → 下载 1 个文件
- 第 3 轮：LLM 认为信息足够 → 停止

**总计**：深度分析阶段最多下载 3-9 个文件（通常 3-6 个）

## 📊 下载统计示例

假设一个典型的 GitHub 仓库：

| 阶段 | 操作 | 文件数量 | 下载内容 |
|------|------|----------|----------|
| **阶段 1** | 获取文件列表 | 1000 个文件路径 | ❌ 不下载内容 |
| **阶段 2** | 生成 Repo Map | 15 个关键文件 | ✅ 下载内容（仅提取符号） |
| **阶段 3** | LLM 深度分析 | 3-9 个文件 | ✅ 下载完整内容并索引 |
| **总计** | 实际下载 | **18-24 个文件** | 约 **2-3%** 的文件 |

**结论**：项目**不会全量下载**，而是智能选择约 2-3% 的关键文件进行分析。

## 🔄 问答阶段的动态下载（JIT）

在用户提问时，如果向量库中缺少相关信息，系统会**按需下载**：

### Just-In-Time (JIT) 文件拉取

**触发条件**：
- 用户提问
- 混合检索（向量 + BM25）返回的结果不足
- LLM 检测到需要更多信息

**流程**：
1. LLM 在回答过程中输出 `<tool_code>path/to/file.py</tool_code>` 标签
2. 系统拦截标签，识别需要下载的文件
3. 从 GitHub 实时下载文件
4. 进行代码分块和向量化
5. 更新向量数据库
6. LLM 基于新信息重新生成答案

**示例**：
- 用户问："这个项目的认证逻辑在哪里？"
- 检索结果不足
- LLM 输出：`<tool_code>app/auth/middleware.py</tool_code>`
- 系统下载该文件并索引
- LLM 基于新文件内容回答

**特点**：
- ✅ 按需下载，不浪费资源
- ✅ 动态扩展知识库
- ✅ 支持无限文件（理论上）

## 🎯 支持的文件处理类型

### 三、代码分块策略

项目对不同类型的文件采用不同的处理策略：

#### 3.1 Python 文件（AST 感知分块）

**处理方式**：
- 使用 Python `ast` 模块解析语法树
- 按类和函数切分
- 大类拆解时注入父类上下文

**优势**：
- 保持代码逻辑完整性
- 函数不会被截断
- 上下文信息丰富

#### 3.2 C-Style 语言（括号层级分块）

**支持语言**：
- Java, JavaScript, TypeScript, Go, C++, C#, PHP, Rust

**处理方式**：
- 基于花括号 `{}` 层级识别代码块
- 提取类/函数名作为元数据

#### 3.3 其他文件（固定行数分块）

**处理方式**：
- Markdown、配置文件等
- 按固定行数（100 行）切分

## 📈 实际处理流程示例

### 示例：分析一个 Flask Web 应用

**仓库结构**：
```
my-flask-app/
├── app/
│   ├── __init__.py
│   ├── main.py          ← 阶段 2 下载（提取符号）
│   ├── models.py        ← 阶段 3 可能下载
│   ├── routes.py        ← 阶段 3 可能下载
│   └── services/
│       ├── auth.py      ← 阶段 3 可能下载
│       └── db.py
├── config.py            ← 阶段 2 下载（提取符号）
├── requirements.txt
├── README.md            ← 阶段 3 自动下载
└── tests/
    └── test_auth.py
```

**处理流程**：

1. **阶段 1**：获取所有文件路径（10 个文件）

2. **阶段 2 - Repo Map 生成**：
   - 下载 `app/main.py`, `config.py` 等 15 个关键文件
   - 提取符号：
     ```
     app/main.py
       [F] create_app
       [F] run_server
     app/services/auth.py
       [C] AuthService
         - login
         - verify_token
     ```
   - 生成包含所有 10 个文件路径 + 符号信息的 Repo Map

3. **阶段 3 - LLM 智能选择**：
   - **Round 1**: LLM 选择 `app/main.py`, `app/services/auth.py` → 下载 2 个文件
   - **Round 2**: LLM 选择 `app/models.py` → 下载 1 个文件
   - **Round 3**: LLM 认为信息足够 → 停止

4. **总计下载**：17-18 个文件（包括阶段 2 的 15 个 + 阶段 3 的 3 个）

5. **问答阶段**：
   - 用户问："数据库连接在哪里？"
   - 如果 `app/services/db.py` 未被索引
   - LLM 输出：`<tool_code>app/services/db.py</tool_code>`
   - 系统实时下载并索引该文件

## ✅ 总结

### 项目处理的内容：

1. ✅ **文本源代码文件**（Python, Java, JS, Go 等）
2. ✅ **配置文件**（JSON, YAML 等）
3. ✅ **文档文件**（Markdown 等）
4. ❌ **不处理二进制文件**（图片、视频、压缩包等）
5. ❌ **不处理依赖目录**（node_modules, venv 等）

### 下载策略：

1. ❌ **不是全量下载**
2. ✅ **智能选择性下载**
   - 阶段 1：只获取文件路径（0 个文件内容）
   - 阶段 2：下载 15-20 个关键文件（提取符号）
   - 阶段 3：LLM 选择 3-9 个文件（深度分析）
   - 问答阶段：按需 JIT 下载
3. ✅ **总计下载约 2-3% 的文件**

### 优势：

- 🚀 **高效**：不下载无用文件，节省时间和带宽
- 🧠 **智能**：LLM 自主选择最关键的文件
- 💾 **节省存储**：向量库只存储关键代码片段
- 🔄 **动态扩展**：问答时按需下载缺失文件
